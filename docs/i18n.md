# Localization

English is the default language of the product and the repository. Supported languages: English, Русский, Español, Deutsch, Français, Italiano, Português, 中文, 日本語 (`en ru es de fr it pt zh ja`).

## Switching the language

- Settings page (`http://127.0.0.1:7777/`): the language picker at the top right.
- Terminal: `node configure.mjs language ja` (`node configure.mjs language` shows the current one).
- `config.json`: `"language": "de"`.

The switch is live: the bridge re-reads the setting within ~2 seconds, redraws the sidebar, renames unnamed builders ("Chat 1a2b"), regenerates the data pack (advancements, town hall dialog) and lets features refresh their own displays. Messages already sent to chat stay as they were.

## Rules for code

- Every user-visible string goes through `t()` from `bridge/i18n.mjs`: in-game chat (`tellraw`), sidebar and nametags, dialogs, books and signs, settings and map pages, CLI output of `configure.mjs`.
- Keys are flat and namespaced by module: `hall.title`, `callout.waiting`, `settings.preset.max`. Placeholders use `{name}`: `t('hall.title', { city })`.
- Plurals: pass `count` and define `key.one` / `key.other` (plus `few` / `many` where the language needs them, e.g. Russian). `Intl.PluralRules` picks the form. Chinese and Japanese only have `key.other`.
- `locales/en.json` is the source of truth: add every new key there first, with natural English. Add the Russian translation to `locales/ru.json` at the same time. The other languages are filled by the localization pass (`node tools/i18n-check.mjs --missing` lists what is missing); missing keys fall back to English.
- Don't localize: log lines (`log(...)`), code comments, identifiers, block ids, Minecraft commands. Swiss shop signs on buildings (e.g. `BAECKEREI`) stay Swiss German on purpose.
- Look texts up when they are shown, not at module load: `t()` at import time freezes the language that was active then.

### Helpers in `bridge/i18n.mjs`

| Helper | Use |
|---|---|
| `t(key, params, lang?)` | The text in the current language (English fallback, then the key itself). |
| `tParts(key, params)` | Minecraft text components in the translated word order. A param given as an object (`{ text, color, click_event… }`) becomes its own component: `announce(tParts('bridge.done.house', { name: { text: s.name, color: 'yellow' }, district: { text: d.name, color: 'gold' }, what }))`. Never glue sentence pieces together in code: word order differs between languages. |
| `tOr(key, fallback, params)` | `t()` that returns `fallback` when no catalog has the key (inline labels during a migration). |
| `has(key)` | Whether a catalog has the key. |
| `strings(prefixes, lang)` | Raw strings for the browser pages (`settings.*`, `map.*`, `building.*`). |
| `setLanguage(code)`, `language()`, `onLanguageChange(fn)`, `reloadCatalogs()`, `LANGUAGES`, `htmlLang()` | Plumbing; the bridge and `Settings` call these. |

### Live switch: what a feature has to do

Texts sent once (chat lines) need nothing. Texts that stay in the world (text displays, signs, books, boss bars, cached nametag or sidebar lines) must be redrawn: implement the feature hook `onLanguage(ctx, lang)` (called through `features.emitSync('onLanguage', lang)` after every switch) and drop your caches there.

### Where well-known texts live

| Prefix | What |
|---|---|
| `feature.<id>.label`, `feature.<id>.desc`, `feature.group.<slug>` | Settings page and `configure.mjs` (the inline `label` / `description` / `group` of a feature are only a fallback; groups: `claude builders city progress privacy extras info`, or a new slug with its own key). |
| `param.<key>.label`, `param.<key>.desc`, `param.<key>.option.<value>` | Parameters on the settings page. |
| `preset.<id>.label`, `preset.<id>.desc` | Presets. |
| `building.<type>` | Building types as players see them (sidebar, chat, map, chronicle). |
| `form.<type>` | Small forms (bench, linden, fountain…). |
| `bridge.*`, `common.*` | Core announcements, welcome, sidebar. |
| `settings.*`, `map.*`, `cli.*` | Settings page, map page, `configure.mjs`. |
| `datapack.*` | Advancement titles and descriptions, the town hall dialog: data packs can't carry translations, so the bridge renders the pack from the catalog of the configured language when it installs it (`datapack/build.mjs` → `packFiles(lang)`), and again after a language switch. |

### Sidebar and nametags

The Minecraft sidebar is narrow. `tools/i18n-check.mjs` measures (CJK glyphs count double):
`building.*` and `form.*` ≤ 20 (the sidebar appends ` 45%`), `bridge.site.summit`, `bridge.score.searching`, `bridge.chat.unnamed` ≤ 26, and any key containing `.sidebar.` / `.nametag.` or ending in `.short` ≤ 26. Name your sidebar and nametag keys that way so they are checked.

## Checking catalogs

```
node tools/i18n-check.mjs            # all languages: missing/extra keys, plural forms, {placeholders}, duplicates, sidebar widths
node tools/i18n-check.mjs ja --missing   # one language, with the English text of every missing key
```

It exits with 1 when anything is wrong.

## Rules for docs

- `README.md` and everything in `docs/` are written in English. Translations of the README live next to it as `README.<lang>.md` (e.g. `README.ru.md`) and are linked from the top of `README.md`.
