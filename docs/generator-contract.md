# Контракт генераторов и моста

Что мост (`bridge/`) ожидает от генераторов зданий (`bridge/buildings.mjs`, собирается из `.dev/parts/*.mjs` через `node .dev/assemble.mjs`) и что он делает с их результатом. Всё здесь обратно совместимо: генератор, который новых полей не знает, продолжает работать, мост подставляет запасной вариант.

## 1. Что уже есть и не должно ломаться

| Экспорт | Что это |
|---|---|
| `BUILDINGS[type](rng)` | Генератор здания. Возвращает `Blueprint` в локальном кадре 0..16 (смещение 2 до участка 21×21 делает мост) |
| `generate(type, seed, options?)` | `BUILDINGS[type](rngFrom(\`${seed}:${type}\`), options)` |
| `square(rng)`, `plaza(rng)` | Главная площадь и площадь квартала (участок целиком) |
| `CATALOG[type]` | `{ label, zones: {core, inner, outer, rural}, unique?: 'district'|'city' }` — выбор типа по зоне |
| `Blueprint#toBuildList({turns, size, offset, clipMin, clipMax})` | Упорядоченный список `{x, y, z, block, decor}` |

Детерминированность обязательна: один и тот же `seed` даёт тот же список. По хэшу списка мост узнаёт, что чертёж изменился.

## 2. Версии генераторов и ремонт

Мост считает версию как `sha256(buildings.mjs + "\0" + blueprint.mjs)`, первые 12 hex-символов, и при старте кладёт копию обоих файлов в `bridge/archive/<версия>/`. Каждый участок помнит, какой версией построен (`plot.gen`).

Если версия сменилась:

- **недостроенный дом**: мост сравнивает уже поставленную часть старого списка с новым списком, убирает лишнее и строит дальше по новому, пропуская блоки, которые уже стоят правильно;
- **готовые дома, площади, главная площадь** (функция «Ремонт вместо сноса»): бригада ремонта меняет только разницу. Сначала снимает декор, которого больше нет или который поменялся, затем лишнюю конструкцию сверху вниз, потом ставит новое в обычном порядке стройки. Неизменные блоки не трогаются.

Отсюда требования к генераторам:

1. Архивированная копия должна загружаться сама по себе: `buildings.mjs` импортирует только `./blueprint.mjs` (относительный путь), никаких других модулей проекта.
2. Не удалять тип из `BUILDINGS`, пока в городе есть такие здания. Если тип всё же исчез, мост оставляет старые дома как есть.
3. Сид и поворот участка не меняются, поэтому хорошо, когда правка генератора меняет только то, что действительно поменялось. Перестановка порядка случайных вызовов `rng` в начале генератора перекрашивает весь дом, и ремонт превращается в перестройку.

`bridge/archive/legacy.txt` указывает каталог версии, которой построены участки без поля `gen` (город до появления версий). Каталоги из архива не удалять, пока на них ссылаются участки (`/status` → `generators.outdatedPlots`).

## 3. Этапы роста дома (новое; генераторам нужно реализовать)

С функцией «Экономика чатов» дом чата растёт этапами, а не строится сразу целиком:

| Этап | Что это | Когда (по умолчанию) |
|---|---|---|
| 1 | Маленький дом: жилое ядро (1 этаж + крыша) | чат набрал 20 действий |
| 2 | Полный дом (то, что генераторы строят сейчас) | 80 действий |
| 3 | Расширение: пристройка, сад, флаг, теплица, терраса | 200 действий |

Переход между этапами мост делает тем же диффом, что и ремонт, поэтому **этап N+1 должен содержать этап N почти целиком**: добавлять, а не перекладывать. Допустимо убрать то, что мешает (временная крыша этапа 1 над будущим вторым этажом), но стены, пол и интерьер этапа 1 должны остаться на местах.

Контракт:

```js
// Сколько этапов умеет тип (1..3). Типа нет в STAGES или STAGES не экспортирован = 1 этап.
export const STAGES = { chalet: 3, townhouse: 3, hut: 2 /* … */ };

// options.stage = 1..STAGES[type]; без options генератор строит последний этап.
export function generate(type, seed, options = {}) {
  return BUILDINGS[type](rngFrom(`${seed}:${type}`), options);
}
export function chalet(rng, { stage = 3 } = {}) { /* … */ }
```

- `rng` расходуется одинаково на всех этапах. Сначала тянуть все случайные решения, потом рисовать по этапу. Иначе этап 2 будет другим домом, а не продолжением этапа 1.
- Мост просит `stage = min(этап участка, STAGES[type])`. Если генератор этапов не знает, этапы 1 и 2 совпадают (полный дом), а на этапе 3 мост сам добавляет во двор флагшток со швейцарским флагом и клумбы (`yardExtras` в `bridge/smallforms.mjs`) на свободных клетках газона.
- Общественные здания (церковь, башня, кафе, построенные «для квартала») мост просит сразу последним этапом.
- `square` и `plaza` этапов не имеют.

## 4. Маркеры (side-channel; генераторам нужно реализовать)

Для «Жизни города» (жители по распорядку, сидящие люди, животные, хроника у двери) мосту нужны точки внутри и вокруг здания. Блоки они не меняют и в хэш чертежа не входят.

```js
// В Blueprint (blueprint.mjs):
bp.mark(kind, x, y, z, { facing, data })            // в локальном кадре генератора, как bp.set
bp.toMarkerList({ turns, size, offset, clipMin, clipMax })
// -> [{ kind, x, y, z, facing?, data? }] с тем же сдвигом и поворотом, что и toBuildList
//    (facing поворачивается так же, как facing у блоков)
```

| kind | Где ставить | Что мост с ним делает |
|---|---|---|
| `door` | клетка перед главной дверью, снаружи | хроника (кафедра рядом, зона клика), куда приходит строитель |
| `lectern_spot` | свободная клетка у входа для кафедры | книга «Хроника дома» |
| `bed` | изголовье кровати (`data: {owner: 'family'\|'guest'}`) | спящий строитель «идёт домой», жители ночью |
| `workstation` | блок профессии или место для него (`data: {profession}`) | профессия жителя |
| `seat` | клетка, где сидят (ступень-стул, скамья), `facing` = куда смотрит | сидящие люди: кафе днём, церковь по воскресеньям, Stube |
| `bell` | колокол | коммиты, бой часов |
| `clock_spot` | центр циферблата, `facing` = наружу | стрелки SBB-часов |
| `light` | клетка у окна изнутри | свет в окнах, пока чат работает |
| `pasture` | центр загона (`data: {w, d}`) | коровы и козы |
| `pet_spot` | место кошки или собаки | кошка, сенбернар у хижины |
| `sign_spot` | место таблички у входа | (резерв) |
| `painting_spot` | стена под картину | (резерв) |

Пока маркеров нет, мост выводит то, что может, из самого списка блоков (`bridge/plotmeta.mjs`): колокола, трубы-костры, двери, клетки за окнами для света, циферблаты по рисунку `clockFace`, свободные клетки газона. Когда маркеры появятся, мост берёт их в первую очередь.

## 5. Проверки

- `node tools/validate-blocks.mjs`: все блоки и свойства существуют в 1.21.11 (прогоняет все типы; с этапами прогонять каждый этап).
- `.dev/ingame-check.mjs`: постройка на тестовом сервере, ничего не отваливается.
- Для этапов: список этапа N+1 содержит ≥ 90% позиций этапа N с тем же блоком (это проверяет мост при первом переходе и пишет в лог `removed / already right / to place`).
